# Консоль администрирования RAS — подробное руководство

Консоль администрирования кластеров 1С:Предприятия 8 на Java (JavaFX). Подключается к нескольким серверам администрирования (`ras`) одновременно и повторяет возможности стандартной консоли кластера.

## Что такое скачанный архив

`1cits_exe_java-api-8.3.11_java-api-8.3.11.zip` — официальная клиентская библиотека 1С для сервера администрирования (RAS). Она общается с `ras` по его собственному бинарному протоколу, тому же, что использует `rac`. Внутри лежат jar-файлы (`com._1c.v8.ibis.admin-1.6.7.jar` и зависимости), javadoc (копия в `docs/ras-api`) и пример консоли на Swing. Вся работа с кластером в этой консоли идёт через интерфейс `IAgentAdminConnection` из этой библиотеки.

## Подготовка сервера 1С

На каждом сервере, которым нужно управлять, должна работать служба `ras`:

```
ras cluster --service --port=1545 localhost:1540
```

Зарегистрировать её как службу Windows можно скриптом `RegMSC.cmd` из каталога платформы, либо так:

```
sc create "1C:Enterprise RAS" binPath= "\"<каталог платформы>\bin\ras.exe\" cluster --service --port=1545 localhost:1540" start= auto
```

Порт 1545 должен быть открыт с машины, где запускается консоль.

## Сборка и запуск

Нужен JDK 17+ с JavaFX. Подходит Axiom JDK Full, который ставится вместе с платформой 1С; скрипты находят его сами.

```
powershell -ExecutionPolicy Bypass -File build.ps1
dist\RasConsole\run.cmd
```

Отдельное приложение со встроенной Java, которому не нужен установленный JDK:

```
powershell -ExecutionPolicy Bypass -File package.ps1
dist\app\RasConsole\RasConsole.exe
```

`RasConsole.exe` и `RasCli.exe` — только запускатели. Рядом с ними должны лежать папки `app` (программа и `RasConsole.cfg`) и `runtime` (встроенная Java). Если скопировать один exe, при запуске будет ошибка `Error opening "...\app\RasConsole.cfg"`.

- Для переноса на другой компьютер или в другую папку используйте архив `dist\RasConsole-portable.zip`: его собирает `package.ps1`, распаковывать можно куда угодно.
- Для Linux `package.ps1` собирает `dist\RasConsole-linux.tar.gz` — см. раздел «Linux».
- Чтобы запускать с рабочего стола, создайте ярлык: правой кнопкой по `RasConsole.exe` → «Отправить» → «Рабочий стол (создать ярлык)».

### Публичная сборка без библиотеки 1С

`package.ps1 -Public` собирает `dist\public\RasConsole-<версия>-windows.zip` и `…-linux.tar.gz` без jar-файлов 1С. Только такую сборку можно выкладывать публично: библиотеку 1С разрешено использовать лишь пользователям «1С:Предприятия 8». В конце скрипт проверяет, что файлов 1С в сборке нет.

При первом запуске такая сборка ищет архив Java API с ИТС рядом с программой и в «Загрузках». Если не находит, открывает окно с кнопками «Открыть страницу ИТС» и «Выбрать архив…». В командной строке есть команда `RasCli install-api <архив.zip>`.

Из архива (в том числе вложенного) берутся только файлы `lib/*.jar` под своими именами, поэтому пути внутри архива не могут записать файлы куда-то ещё. Архив без `com._1c.v8.ibis.admin-*.jar` отклоняется. Библиотека кладётся в `%APPDATA%\RasConsole\api` (`~/.rasconsole/api` в Linux) и при каждом запуске подключается отдельным загрузчиком классов (`Boot.java`). В сборке с библиотекой (`lib\` рядом с программой) этот шаг пропускается.

Проверка связи без UI:

```
cd dist\RasConsole
java -cp "ras-console.jar;lib/*" ru.rasconsole.tools.Probe server-1c:1545 [админ_кластера пароль]
```

## Возможности

- Несколько серверов RAS в одном дереве, с группами («Прод», «Тест») и пометкой продуктивных серверов.
- Кластеры: свойства, регистрация, удаление, применение требований назначения.
- Администраторы центрального сервера и кластера.
- Менеджеры и сервисы кластера.
- Рабочие серверы: свойства, диапазоны портов, добавление и удаление; рабочие процессы сервера; требования назначения функциональности (добавление, изменение, порядок, удаление).
- Информационные базы: создание (с созданием БД или без), свойства, блокировка сеансов и регламентных заданий, удаление (оставить, удалить или очистить БД).
- Сеансы: просмотр, завершение с сообщением, прерывание серверного вызова, блокировки сеанса, автообновление.
- Соединения: просмотр, отключение, блокировки соединения.
- Блокировки по кластеру и по ИБ.
- Рабочие процессы с соединениями и сеансами процесса.
- Профили безопасности: виртуальные каталоги, COM-классы, внешние компоненты и модули, приложения, интернет-ресурсы.
- Счётчики потребления ресурсов (текущие и накопленные значения, сброс) и ограничения.

- Перезапуск рабочих процессов (rphost): «Перезапустить…» для выбранных процессов или «Перезапустить все…».

Если операции нужны права, консоль сама спросит администратора кластера или пользователя ИБ и повторит операцию.

## Повседневная работа

- **Поиск в таблицах.** Над каждой таблицей есть строка поиска по всем колонкам. Несколько слов ищутся одновременно: «иванов buh» найдёт сеансы Иванова в базах с «buh» в имени.
- **Отбор по значению.** Правый щелчок по ячейке любой таблицы — пункты:
  - «Отбор: «Пользователь» = ИвановАА» — оставить строки с таким значением;
  - «Исключить: … ≠ …» — убрать такие строки;
  - «Копировать значение».

  Отборы по разным колонкам складываются друг с другом и с поиском. У колонки с отбором в заголовке значок воронки. Рядом с поиском появляется кнопка «Снять отборы (N)», а в контекстном меню — «Снять отбор по колонке» и «Снять все отборы». «Завершить отфильтрованные…», «Экспорт в CSV» и счётчик «Найдено» учитывают отборы.
- **Экспорт в CSV.** Кнопка «Экспорт в CSV…» сохраняет видимые строки (с учётом поиска) в CSV, который сразу открывается в Excel.
- **Число сеансов в дереве** — «Сеансы (12)» у кластера, базы и рабочего процесса. Число загружается в фоне при раскрытии узла (если пароль кластера не сохранён — после первого открытия списка) и обновляется при каждом обновлении списка, в том числе при автообновлении.
- **Подсветка сеансов.** Красным выделены сеансы, которые ждут блокировку; оранжевым — сеансы, которые держат блокировку и задерживают других.
- **Ожидания на блокировках** (узел кластера). Дерево «кто кого держит»: сверху виновник, под ним ожидающие его сеансы. Виновника можно завершить прямо отсюда.
- **Лицензии** (узел кластера). Кто какую лицензию занял: сеансы и рабочие процессы, серия ключа, сетевой ли ключ, максимум пользователей. «Сводка по ключам» показывает, сколько лицензий занято по каждому ключу.
- **Завершение сеансов** — с сообщением пользователям и исключениями: не трогать Конфигуратор, фоновые задания, COM-соединения и т. д. Перед завершением видно, какие сеансы попадут под действие. «Завершить отфильтрованные…» завершает все сеансы, найденные поиском.

## Регламентные работы

«Регламентные работы…» — в узле кластера и в списке информационных баз.

1. Отметьте базы, задайте начало и окончание блокировки, сообщение и код разрешения (вход во время блокировки — с параметром `/UC<код>`).
2. При необходимости включите блокировку регламентных заданий и завершение текущих сеансов. Конфигуратор по умолчанию не завершается.
3. Консоль обработает базы по очереди, при необходимости спросив пользователя ИБ, и покажет отчёт по каждой.
4. После работ запустите мастер ещё раз в режиме «Снять блокировку».

**По расписанию.** Флажок «По расписанию» в мастере: в момент «Начало» консоль заблокирует базы (и, если отмечено, завершит их сеансы), в момент «Окончание» снимет блокировку. Пример — «заблокировать в 22:00, выгнать пользователей, снять блокировку в 23:30».

- Перед сохранением задания консоль проверяет доступ к каждой базе. Если пароль пользователя ИБ не сохранён, она спросит его сейчас — отметьте «Запомнить пароль», ведь ночью спросить будет некого.
- Задание выполняет эта консоль, поэтому в назначенное время она должна быть запущена (можно свернуть в трей). Если консоль была закрыта и задание опоздало больше чем на 15 минут, оно не выполняется и помечается «пропущено».
- Окончание блокировки сеансов передаётся и серверу. Даже если консоль к тому времени закроют, вход в базу откроется сам; блокировка регламентных заданий в этом случае останется.
- Список заданий — «Действия → Запланированные работы…»: состояние, результат по каждой базе, отмена, «Снять блокировку сейчас». Результат приходит уведомлением в трей и во внешние каналы, всё пишется в журнал действий. Задания хранятся в `schedule.properties`.

## Наблюдение

- **Сводка по серверам** — открывается на узле «Серверы RAS». По каждому кластеру всех серверов: сеансы (всего, активные, спящие), ожидающие блокировок, рабочие процессы и их память, самый долгий текущий вызов, лицензии, проблемы. Обновляется каждые 10 с. Двойной щелчок открывает кластер в дереве.
- **Проблемы:** рабочий процесс превысил порог памяти, «Время вызова (текущее)» больше порога, «Захвачено СУБД (текущее)» больше порога (сеанс держит соединение с СУБД), сеанс ждёт блокировку дольше порога, сеансов или занятых лицензий в кластере больше порога, нет связи с сервером. Пороги задаются в «Настройки…» (кнопка в сводке или «Файл → Настройки…»), вкладка «Наблюдение»; 0 — не проверять.
- **Уведомления в трее.** Если включить «Наблюдать в фоне…», консоль раз в интервал опрашивает все серверы, даже когда свёрнута, и показывает новые проблемы всплывающим уведомлением Windows. О проблеме, которая уже была, повторно не сообщает — в том числе после восстановления связи. Отдельное уведомление «Связь с … восстановлена» можно выключить. Щелчок по уведомлению открывает сводку. Настройки — в `%APPDATA%\RasConsole\settings.properties`.
- **Оповещения наружу** — вкладка «Оповещения» в настройках. Те же сообщения (проблемы, восстановление связи, запланированные работы) уходят во включённые каналы:
  - **Telegram** — токен бота от @BotFather и chat_id: число, у групп отрицательное, или `@канал`. Бота нужно добавить в группу или канал.
  - **Webhook** — POST JSON с полями `text`, `title`, `message`, `source`, `host`, `time`. Поле `text` понимают входящие webhook Slack, Mattermost и Rocket.Chat; для своего обработчика есть остальные поля.
  - **Почта** — SMTP с SSL/TLS (465), STARTTLS (587) или без шифрования (25), с авторизацией или без. Получателей можно указать несколько через запятую.
  - Кнопка «Отправить тестовое сообщение» проверяет каналы с текущими значениями полей, ещё до сохранения.
  - Токен бота и пароль SMTP хранятся зашифрованными вместе с паролями серверов. Если хранилище недоступно, они действуют только до закрытия программы.
- Кластеры, пароль к которым ещё не введён и не сохранён, опрашиваются без запросов пароля и показываются со статусом «нужна авторизация». Чтобы они попадали в сводку, сохраните пароль («Запомнить пароль»).

## Тяжёлые сеансы и группы сеансов

- **Тяжёлые сеансы** (узел кластера) — только сеансы с нагрузкой сейчас или за последние 5 минут. Сверху — те, кто больше всего грузит сервер: процессор за 5 минут плюс длительность текущего вызова. В колонках: процессор, текущий вызов, время СУБД, память, объём данных СУБД, чтение и запись, кого ждёт сеанс. Жёлтым выделены вызовы дольше порога из настроек, красным — ожидающие блокировку. Автообновление включено; завершить сеанс или прервать вызов можно прямо отсюда.
- **Сеансы по группам** (узел кластера) — группировка по пользователю, компьютеру, паре «пользователь и компьютер», приложению, базе или рабочему процессу. Для каждой группы видно число сеансов, лицензий, активных и спящих, процессор, память, самый ранний вход, а также базы, компьютеры и приложения группы. Жёлтым выделены пользователи и компьютеры, занявшие больше одной лицензии. Двойной щелчок показывает сеансы группы; «Завершить сеансы группы…» завершает их.

## Избранные базы и наблюдение за базами

- **Избранные базы** — первый раздел дерева. Туда попадают базы с любых серверов: «В избранное» в меню базы или в списке баз (можно сразу несколько). У избранной базы — те же действия, что в дереве кластера: открыть в 1С, свойства, сеансы, блокировки. Порядок меняется командами «Выше в избранном» и «Ниже в избранном». Список хранится в `favorites.properties`.
- **Наблюдение за входами** — «Наблюдать за входами» в меню базы. При каждом фоновом опросе консоль сравнивает сеансы базы с прошлым опросом и записывает, кто вошёл и кто вышел: время, пользователь, компьютер, приложение, номер и начало сеанса. При первом опросе после запуска записывается, кто уже в базе.
  - Журнал — «Журнал входов» в меню базы или «Действия → Журнал входов в наблюдаемые базы…». Файлы `sessions-ГГГГ-ММ.tsv` лежат в папке истории и открываются в Excel.
  - Пока за какой-нибудь базой ведётся наблюдение, фоновый опрос работает, даже если уведомления выключены. Сеанс короче интервала опроса (по умолчанию 60 с) может не попасть в журнал.

## Свойства базы

Форма свойств информационной базы разбита на разделы:

- **Основное** — имя, описание, уровень безопасности.
- **База данных** — СУБД, сервер, база, пользователь и пароль, язык, смещение дат.
- **Блокировка начала сеансов** — с пояснением про код разрешения.
- **Регламентные задания и лицензии** — блокировка регламентных заданий, выдача лицензий сервером, резервирование рабочих процессов.
- **Безопасность** — профиль безопасности и профиль безопасного режима.
- **Внешнее управление сеансами**.
- **Служебное** — ID базы.

Окно «Блокировка сеансов…» показывает только свои разделы.

Даты — начало и конец блокировки здесь и в мастере регламентных работ — выбираются в календаре. Время вводится рядом в виде `чч:мм`. Кнопки рядом с полем:

- «Сейчас» — подставить текущее время;
- «+1 ч» — сдвинуть время на час;
- «✕» — очистить дату (пустой конец блокировки — до снятия вручную).

## Изменение параметров нескольких баз

«Изменить у нескольких…» в списке информационных баз (выделите базы). Отметьте параметры, которые нужно поменять:

- блокировка регламентных заданий;
- выдача лицензий сервером;
- профиль безопасности и профиль безопасного режима;
- резервирование рабочих процессов;
- сервер СУБД, пользователь и пароль СУБД;
- смещение дат.

Остальные параметры баз не меняются. Консоль обработает базы по очереди и покажет результат по каждой. Каждое изменение пишется в журнал действий.

## Вкладки и оформление

- **Вкладки.** Справа всегда есть основная вкладка — она показывает узел, выбранный в дереве. «Открыть в новой вкладке» (в меню узла, Ctrl+T или щелчок средней кнопкой мыши) закрепляет узел в отдельной вкладке. Например, можно держать рядом сеансы двух разных баз. Ctrl+W закрывает вкладку.
- **Тёмная тема** — «Настройки… → Оформление». Применяется сразу ко всем окнам.

## Отчёт по серверам

«Действия → Отчёт по серверам (Excel/HTML)…» опрашивает все серверы и сохраняет одну книгу `.xlsx` или страницу `.html`. В отчёте шесть листов:

- серверы: состояние, версия RAS, число кластеров, баз, сеансов и лицензий;
- кластеры;
- рабочие серверы;
- информационные базы: число сеансов, пользователей и лицензий;
- рабочие процессы: память и время вызова;
- лицензии: кто какую занял.

У листов закреплён заголовок и включён автофильтр. Кластеры без сохранённого пароля попадают в отчёт с пометкой «нужна авторизация». То же из командной строки: `RasCli report отчёт.xlsx` — например, по расписанию раз в неделю.

## Linux

Консоль работает и в Linux: она подключается к RAS по сети и не использует COM. Архив `dist\RasConsole-linux.tar.gz` содержит программу, библиотеки и скрипты запуска.

- Нужна Java 17+ с JavaFX: Axiom JDK Full или Liberica JDK Full (вариант Full). Скрипты ищут её в `JAVA_HOME`, в стандартных каталогах Axiom/Liberica и в `PATH`. Если в найденной Java нет JavaFX, скрипт так и скажет. Командной строке JavaFX не нужна.
- Запуск окна — `./rasconsole.sh`, командная строка — `./rascli.sh help`. Настройки хранятся в `~/.rasconsole`.
- Пароли сохраняются, если установлен `secret-tool` (пакет `libsecret-tools`) и работает связка ключей (GNOME Keyring, KWallet). Файл паролей шифруется AES-GCM, а случайный ключ хранится в связке ключей пользователя. Без `secret-tool` пароли действуют до закрытия программы.
- «Открыть в 1С» и «Выключить» rphost через `rac` ищут платформу в стандартном каталоге установки 1С.
- Уведомления в трее зависят от окружения рабочего стола (нужна поддержка значков в трее). Оповещения в Telegram, на почту и webhook работают везде.

## Версии платформы

Консоль работает с RAS любой версии: проверено на 8.3.27.1989 и 8.5.4.1683, полный набор операций с одинаковым результатом.

Но **служба RAS на сервере должна быть той же версии, что и агент сервера 1С (ragent)**. Это ограничение самой 1С — даже штатный `rac` в такой паре выдаёт «Различаются версии клиента и сервера (8.5.4.1683 - 8.3.27.1989), клиентское приложение: Сервер администрирования». Первой в сообщении идёт версия RAS, второй — версия агента.

- **Частая причина — RAS запущен без адреса агента.** Тогда он подключается к `localhost:1540`. Если на сервере два агента — 8.3 на 1540 и 8.5 на 2540 — то RAS 8.5, запущенный как `ras cluster --port=2545` без адреса, уходит к агенту 8.3. Консоль распознаёт эту ошибку и подсказывает, что указать.
- Если на одном сервере работают кластеры разных версий, запустите для каждого агента свой RAS той же версии, на своём порту и **с явным адресом своего агента**. В консоли добавьте оба адреса:
  ```
  ras 8.3 (из каталога платформы 8.3):  ras cluster --daemon --port=1545 localhost:1540
  ras 8.5 (из каталога платформы 8.5):  ras cluster --daemon --port=2545 localhost:2540
  Windows — то же с --service вместо --daemon: ras cluster --service --port=<порт RAS> localhost:<порт агента>
  ```
  Проверить, куда смотрит запущенный RAS: `ps -eo pid,args | grep '[r]as '` — последний параметр `host:port` и есть адрес агента. Если его нет, используется `localhost:1540`.
- Агенту 8.5 при этом нужны свои порты и свой каталог кластера: `-port 2540 -regport 2541 -range 2560:2591 -d <отдельный srvinfo>`. Агент с портом менеджера кластера (`-regport`) или каталогом `srvinfo`, занятыми агентом 8.3, не запускается — проверено.
- «Версия RAS» в карточке сервера — это версия службы RAS (её возвращает `getAgentVersion`).
- Для «Выключить» rphost консоль берёт `rac.exe` той же версии, что и RAS, если она установлена, иначе самую новую 8.3. Оба варианта проверены с RAS 8.5.

Если RAS отвечает, но сам не может подключиться к агенту (агент остановлен или в `ras` указан неверный адрес), консоль пишет: «служба RAS работает, но не может подключиться к агенту сервера 1С <адрес>».

## Диагностика сети

«Диагностика сети…» есть в меню сервера, на его карточке и в «Действия». Без выбранного сервера консоль спросит адрес. Проверка идёт по шагам, у каждого — время и подсказка, что делать:

1. Имя сервера в DNS.
2. Ping. Если ICMP закрыт, это только замечание.
3. Порт RAS. Консоль различает «порт закрыт» (компьютер ответил отказом — служба ras не запущена или порт другой) и «нет ответа» (файрвол или потеря сети).
4. Ответ RAS: его версия и связь с агентом. Отдельно распознаются ошибка разных версий и случай, когда RAS не может подключиться к агенту.
5. Имена и порты менеджеров кластеров, а также порт агента 1540. Они нужны для запуска 1С, Конфигуратора и стандартной консоли с этого компьютера, но не для работы через RAS, поэтому показываются как замечания.

В результате указан адрес, к которому шло подключение. Это важно, когда у имени несколько адресов: Java берёт первый, и если он нерабочий, подключения не будет.

Кнопки: «Проверить порты 1С» (1540, 1541, 1545) и «Копировать отчёт» — например, чтобы отправить сетевикам.

## Недоступные серверы и таймауты

- **Проверка при запуске.** Сразу после запуска консоль в фоне проверяет все серверы. Пока проверка идёт, сервер показан жёлтой точкой с пометкой «— проверка связи…», а не красным. Красным сервер становится только после того, как подключиться не удалось дважды подряд. Повторные опросы уже недоступного сервера не перекрашивают его в жёлтый, поэтому он не мигает. В сводке до первого ответа написано «Опрос серверов…».
- **Подключение** (вместе с поиском имени в DNS) ограничено 5 секундами. Если сервер не ответил, консоль сообщает «Сервер … не ответил за 5 с».
- **Пауза после неудачи.** После неудачного подключения следующие 15 секунд операции с этим сервером сразу получают ту же ошибку с пометкой «повторная попытка через N с», а не ждут каждая свою попытку. Раскрытие сервера в дереве или «Подключиться / обновить» в его меню пробуют подключиться сразу.
- **Таймаут ответа** на обычный запрос задаётся в параметрах сервера («Таймаут ответа, с», по умолчанию 10).
- **Долгие операции** — создание и удаление ИБ, регистрация и удаление кластера и рабочего сервера — идут через отдельное соединение с таймаутом 10 минут. Создание ИБ с базой данных занимает от нескольких секунд до минут, и короткий таймаут его обрывал.
- **Подсветка.** Недоступный сервер выделен в дереве красным фоном, с пометкой «— нет связи» и красной точкой на иконке. Группа, в которой есть недоступный сервер, тоже подсвечивается. В сводке такие серверы — красные строки с понятной причиной: «сервер не отвечает», «подключение отклонено: служба RAS не запущена или порт закрыт», «имя сервера не найдено (DNS)».

## Безопасность

- **Продуктивные серверы.** В параметрах сервера отметьте «Продуктивный сервер». Такой сервер выделяется в дереве красным, а опасные действия (удаление, завершение сеансов, перезапуск процессов, регламент, копирование настроек в него) требуют отдельного флажка «Я понимаю, что действие выполняется на продуктивном сервере».
- **Журнал действий администратора** — «Действия → Журнал действий администратора…». Все изменения пишутся в `audit.log`: время, пользователь Windows, сервер, объект, действие и результат, включая ошибки. Журнал ведётся всегда. Папка по умолчанию — `%APPDATA%\RasConsole`, её можно сменить в «Настройки…», например на общую сетевую папку. Командная строка `RasCli` пишет в ту же папку.

### Что учтено в коде

- **Системные программы запускаются по полному пути.** Это `powershell.exe` для шифрования паролей и `explorer.exe`. Иначе Windows сначала ищет программу в текущей папке, и подложенный туда `powershell.exe` получил бы пароли. В Linux `secret-tool` ищется только в абсолютных каталогах `PATH`.
- **Адрес сервера проверяется.** Допустимы буквы, цифры, точка, дефис и IPv6 в скобках; адрес не может начинаться с «-». Адрес передаётся аргументом `rac`, поэтому чужой файл импорта не подсунет `rac` свои параметры. При импорте неверные адреса и порты пропускаются, число записей ограничено.
- **Экспорт в CSV, копирование в буфер и журнал входов не создают формул Excel.** Описания блокировок, имена пользователей и компьютеров приходят с сервера. Значение, начинающееся с `=`, `+`, `-` или `@`, сохраняется с апострофом. Числа не меняются.
- **`.v8i` и запуск 1С защищены от подмены параметров.** Переводы строк и управляющие символы из имени и описания базы не попадают в файл `.v8i`. Имена с кавычками не передаются в командную строку 1С.
- **Оповещения:**
  - токен бота не попадает в тексты ошибок;
  - адреса почты проверяются, поэтому в письмо и команды SMTP нельзя дописать свои строки;
  - сертификат SMTP и HTTPS проверяется.
- **Код разрешения заданий по расписанию** хранится зашифрованным вместе с паролями, а не в `schedule.properties`.

### Что остаётся на стороне инфраструктуры

- **Протокол RAS не шифруется.** Имена и пароли администраторов кластера идут по сети открыто — так устроена сама 1С, у `rac` то же самое. Открывайте порт RAS (1545) только для компьютеров администраторов: межсетевой экран или VPN.
- **Пароль администратора кластера при «Выключить» rphost передаётся `rac` в командной строке** (`--cluster-pwd`). Другого способа `rac` не поддерживает. Пока `rac` работает (несколько секунд), командную строку процесса видят администраторы этого компьютера, а в Linux — все пользователи. Выключайте процессы с компьютера, где нет посторонних пользователей.
- **`RasCli` с `--cluster-pwd`, `--ib-pwd`:** пароль виден в списке процессов и в истории команд. Для Планировщика лучше один раз сохранить пароль в консоли.
- **Шифрование SMTP «без шифрования (25)»** передаёт пароль почты открытым текстом. Используйте SSL/TLS или STARTTLS.

## Копирование настроек между кластерами

«Копировать настройки…» в узле кластера. Копирует в другой кластер — на этом же или на любом другом сервере из списка — профили безопасности со всеми разрешениями, счётчики и ограничения потребления ресурсов. Одноимённые объекты в целевом кластере перезаписываются, по итогам показывается отчёт. Требования назначения не копируются: они привязаны к конкретным рабочим серверам.

## Учётные данные

- Список серверов (компьютер, порт, имя, таймаут, имя администратора агента) хранится в `%APPDATA%\RasConsole\servers.properties`.
- Пароли сохраняются, если в окне входа отметить «Запомнить пароль». Пароль записывается только после того, как сервер его принял.
  - Файл — `%APPDATA%\RasConsole\credentials.dat`. Он зашифрован Windows DPAPI ключом текущего пользователя Windows (через стандартный .NET `ProtectedData`, вызываемый из PowerShell; дополнительные библиотеки не нужны).
  - На другом компьютере или под другим пользователем Windows файл не расшифровать. Программы, запущенные под вашей учётной записью, расшифровать его могут — так же защищены сохранённые пароли RDP и браузеров.
  - Если сохранённый пароль перестал подходить, консоль спросит новый и перезапишет его.
  - «Файл → Забыть сохранённые пароли…» удаляет файл. Удаление сервера из списка удаляет и его пароли.
- Без флажка пароль хранится только в памяти до закрытия программы.
- В Linux вместо DPAPI используется связка ключей пользователя — см. раздел «Linux».

## Импорт и экспорт списка серверов

Кнопки «Импорт…» и «Экспорт…» над деревом (а также меню «Файл»).

- **Экспорт** открывает список серверов с флажками. Отметьте нужные и выберите файл `*.rasservers`. Пароли в файл не попадают.
- **Импорт** читает файл и показывает серверы с флажками. Серверы, которые уже есть в списке (совпадают компьютер и порт), помечены «уже в списке» и пропускаются.

Формат файла такой же, как у `servers.properties`, его можно править вручную.

## Доменная авторизация

Аутентификация ОС (доменная) через RAS не работает. Программный интерфейс принимает только имя и пароль, а администратор кластера с одной лишь «Аутентификацией ОС» не входит ни под каким вариантом имени — проверено на 8.3.27. Кроме того, при управлении через RAS сервер не даёт оставить кластер без администратора с паролем. Для работы через консоль заведите администраторам вход по паролю (можно в дополнение к ОС-аутентификации).

## Перезапуск рабочих процессов

«Перезапустить…» в списке рабочих процессов, «Перезапустить все рабочие процессы…» у рабочего сервера, `RasCli restart-processes` в командной строке.

Процесс выключается **только средствами кластера** — то же, что «Выключить» в стандартной консоли. Кластер выключает rphost, переносит соединения и запускает новый процесс; несколько секунд старый и новый работают одновременно. Команда идёт через RAS, поэтому работает и для серверов 1С на Linux, и без прав администратора Windows на сервере. Принудительного завершения средствами ОС (`taskkill`, `kill`) в консоли нет.

- В Java API 1.6.7 этой команды нет: консоль вызывает `rac.exe process turn-off` из платформы 1С, установленной на этом компьютере. По умолчанию используется самая новая 8.3. Учётные данные кластера консоль передаёт сама.
- Если `rac.exe` не найден, консоль сообщит об этом и ничего не выключит. Установите на компьютер администратора платформу 1С (достаточно компонента администрирования сервера).

Перед выключением консоль показывает, сколько сеансов на процессах.

## Удобство

- **Консоль помнит своё состояние** — `%APPDATA%\RasConsole\ui.properties`: размер и положение окна, разделитель, раскрытые и выбранный узлы дерева, ширину, порядок и видимость колонок каждой таблицы.
- **Горячие клавиши:** Ctrl+F — поиск в таблице (или в дереве), Ctrl+Shift+F — поиск по всем серверам, F5 — обновить, Enter — свойства, Delete — удалить, завершить сеанс или отключить соединение, Ctrl+C — скопировать выделенные строки (вставляются в Excel по колонкам), Esc в поле поиска — очистить.
- **Кнопки с иконками и цветом.** У команд в панелях, диалогах и меню есть иконки. Ключевые команды выделены цветом: красный — удаление, завершение сеансов, отключение, прерывание вызова; зелёный — создание и добавление; оранжевый — блокировки, регламентные работы, перезапуск процессов; синий — «Открыть в 1С» и «Конфигуратор». Кнопки, которым нужно выделение строк, бледные, пока ничего не выбрано. Если кнопки не помещаются по ширине, они переносятся на вторую строку, а не прячутся.
- **Закладки и недавние** — меню «Переход»:
  - Ctrl+Shift+1…9 ставит закладку на выбранный узел (сервер, базу, раздел), Ctrl+1…9 переходит к нему — узлы по дороге раскрываются и загружаются;
  - Ctrl+E показывает 15 последних узлов;
  - закладки и недавние запоминаются между запусками.
- **Интервал автообновления** — рядом с флажком «Автообновление»: 5, 10, 15, 30 или 60 с. Выбор запоминается отдельно для списков и для сводки по серверам.
- **Поиск в дереве** — поле над деревом, Enter переходит к следующему совпадению среди загруженных узлов.
- **Поиск по всем серверам** — кнопка «Везде…» (Ctrl+Shift+F): базы по имени и описанию, сеансы по пользователю, компьютеру, IP и приложению — на всех серверах и кластерах сразу. Двойной щелчок открывает базу в дереве или сеансы с отфильтрованным пользователем.

## Работа с базами

В списке информационных баз и в узле базы:

- **Открыть в 1С / Конфигуратор** — запускает тонкий клиент или Конфигуратор той же версии, что и сервер (если такая версия установлена; иначе самую новую 8.3).
- **Строка подключения** — копирует `Srvr="сервер:порт";Ref="база";` в буфер обмена.
- **Список баз (.v8i)…** — сохраняет выбранные базы в файл списка баз 1С, который можно раздать пользователям.
- **Шаблоны новых ИБ.** При создании базы можно отметить «Сохранить параметры СУБД как шаблон». В следующий раз консоль предложит шаблон: тип и сервер СУБД, пользователь и пароль, язык, смещение дат подставятся сами. Шаблоны — в `ib-templates.properties`, пароль СУБД зашифрован, как остальные пароли.

## История и графики

**По умолчанию запись выключена.** Включается в «Настройки…» (кнопка в сводке или «Файл → Настройки…») флажком «Записывать историю показателей». Там же задаются папка истории (по умолчанию `%APPDATA%\RasConsole\history\`) и срок хранения (по умолчанию 30 дней). Кнопки «Обзор…», «По умолчанию» и «Открыть» выбирают папку, сбрасывают её и открывают в проводнике. Консоль проверяет, что в папку можно писать.

Когда запись включена, консоль раз в минуту записывает показатели каждого кластера, пока открыта сводка или включено фоновое наблюдение. Кнопка «История…» в сводке показывает графики за 6 часов, сутки, неделю или месяц: сеансы, память rphost (видны утечки), занятые лицензии, ожидания на блокировках и самые долгие вызовы, а также пики за период.

## Сравнение настроек кластеров

«Сравнить настройки…» в узле кластера. Сравнивает с любым кластером на любом сервере из списка: параметры кластера, рабочие серверы, требования назначения (с порядком), профили безопасности со всеми разрешениями, счётчики и ограничения ресурсов. Результат — таблица различий: что есть только в одном кластере и какие свойства отличаются.

## Командная строка

`RasCli.exe` (в сборке `dist\app\RasConsole`) или `rascli.cmd` (в `dist\RasConsole`) — для скриптов и Планировщика Windows. Используются тот же список серверов и сохранённые пароли; действия пишутся в журнал.

```
RasCli servers
RasCli infobases prod
RasCli sessions prod --base buh
RasCli lock prod --base buh,zup --message "Регламентные работы" --code 777 --terminate --exclude Designer
RasCli unlock prod --base buh,zup
RasCli terminate prod --base buh --exclude Designer,BackgroundJob
RasCli restart-processes prod [--worker srv-1c-01]
RasCli report серверы.xlsx [--servers prod,test]
```

Сервер — имя или адрес из списка серверов, либо `host:port`. Если кластеров несколько — `--cluster имя|uuid`. Учётные данные можно передать параметрами (`--cluster-user`, `--cluster-pwd`, `--ib-user`, `--ib-pwd`), но в Планировщике лучше один раз сохранить пароль в консоли под той же учётной записью Windows. Коды завершения: 0 — успешно, 1 — ошибка, 2 — неверные параметры, 3 — нужна авторизация. Полная справка: `RasCli help`.

## Проверено

На локальном агенте 8.3.27.1989 с RAS проверены: подключение, кластеры (изменение свойств, регистрация и удаление), менеджеры, сервисы, рабочие серверы и процессы, требования назначения, профили безопасности со всеми видами разрешений, счётчики и ограничения ресурсов, администраторы кластера и агента с запросом пароля, соединения и блокировки. Операции с информационными базами проверены на PostgreSQL 16.14 для 1С: создание с базой данных, свойства, блокировка сеансов и регламентных заданий, мастер регламента на двух базах (установка и снятие блокировки), удаление вместе с базой данных. На живом сервере также проверены копирование настроек во второй кластер, сводная панель, журнал действий и подтверждение для продуктивного сервера. А ещё: выключение rphost через кластер (`rac process turn-off`) из интерфейса и из командной строки, сравнение настроек двух кластеров, поиск по всем серверам, графики истории, поиск в дереве, восстановление состояния окна, дерева и колонок после перезапуска, команды `RasCli` (блокировка, снятие, завершение сеансов, перезапуск процессов, коды возврата).

Не проверено на живом сервере: «Открыть в 1С» и «Конфигуратор» (на тестовой машине нет лицензии 1С), сохранение `.v8i` и окно выбора шаблона при создании ИБ.

Не проверено на живых сеансах: на тестовой машине нет лицензии 1С, без неё сеансы не создаются. Подсветка сеансов, дерево ожиданий на блокировках, раздел «Лицензии», завершение сеансов по фильтру и уведомления о проблемах проверены на фиктивных данных.

Версия 1.2 проверена на имитации сервера RAS с сеансами, лицензиями и ожиданием блокировки:

- тяжёлые сеансы и группы сеансов;
- избранное;
- журнал входов и выходов;
- изменение параметров трёх баз;
- задание по расписанию: блокировка двух баз, завершение их сеансов и снятие блокировки;
- пороги сеансов, лицензий и ожидания блокировок;
- уведомления о потере и восстановлении связи — без повторов;
- вкладки и тёмная тема;
- отчёт `.xlsx` (открывается в Excel) и `.html`, в том числе `RasCli report` из собранного exe.

Webhook и почта проверены на локальных приёмниках: JSON, SMTP с AUTH LOGIN, русская тема и текст письма.

Не проверены:

- отправка в настоящий Telegram (нужен токен бота);
- SMTP с SSL/STARTTLS на реальном почтовом сервере;
- запуск в Linux: архив и скрипты собраны и проверены на структуру, права и синтаксис, но на Linux с JavaFX консоль не запускалась;
- хранение паролей через `secret-tool`.

## PostgreSQL для 1С на Windows

Если 1С при создании ИБ отвечает «Порядок сортировки не поддерживается базой данных», кластер PostgreSQL инициализирован с неподходящей локалью. Для 1С на Windows его нужно создавать с локалью `Russian_Russia.1251` (кодировка UTF8):

```
initdb -D <каталог данных> -U postgres -E UTF8 --locale=Russian_Russia.1251
```

С локалью `ru-RU` базы данных создаются, но 1С их отвергает. Проверено на PostgreSQL 16.14 для 1С (Postgres Pro) и платформе 8.3.27.

## Ограничения

- В 8.3.27 сервер игнорирует свойства кластера «Интервал перезапуска» и «Допустимый объём памяти»: их не сохраняет и `rac cluster update`.
- RAS хранит на соединении только последнюю авторизацию (агента или одного кластера). Консоль переавторизуется сама при переключении между кластерами и разделами агента.

- **Ошибка библиотеки 1С, которую консоль обходит.** Кодек протокола (`BinaryCodecV1_0` в swp 1.0.3) читает строки и записывает числа и UUID через один общий буфер на всю программу. Когда консоль одновременно опрашивает несколько серверов, потоки затирают буфер друг другу:
  - имена склеиваются из двух строк (например, «…cluster�й кластер» из «Local cluster» и «Локальный кластер»);
  - UUID приходят наполовину обнулёнными;
  - запросы падают с «Ошибка формата сообщения».

  Библиотеки подписаны, подменить класс нельзя, поэтому консоль после создания каждого соединения подставляет обёртку кодека, и каждый его вызов идёт под общей блокировкой. Проверено стресс-тестом на 6 одновременных соединениях: без обёртки запросы ломались и зависали, с ней 1800 из 1800 ответов верные.
- Библиотека относится к версии 8.3.11 (API 1.6.7). Более новые серверы RAS с ней работают, но свойства, добавленные в поздних версиях платформы, консоль не увидит. Если понадобятся, скачайте свежий «Программный Java-интерфейс для административного сервера» с releases.1c.ru, положите jar-файлы в `lib\` и пересоберите проект.
- Если подключение падает с ошибкой `Failed to create a selector`, значит у Java нет права записи во временный каталог. Укажите другой каталог: `set RAS_JAVA_OPTS=-Djdk.net.unixdomain.tmpdir=C:\Temp` перед `run.cmd`.

## Структура

```
src/ru/rasconsole/
  ras/      RasConnection — соединение с RAS, свой поток, авторизация, переподключение; ServerReport — отчёт
  config/   список серверов, пароли, избранное, наблюдение за базами, запись .xlsx
  ui/       главное окно, диалоги, асинхронные вызовы (Fx), узел сервера
  ui/tree/  ленивое дерево: ListNode (таблица + действия), ObjectNode (свойства + разделы)
  ui/form/  форма свойств по getter/setter объектов API, русские подписи
  ui/cluster/ разделы кластера и колонки таблиц, расписание (Scheduler), групповое изменение баз
  tools/    Probe — проверка связи из командной строки; IconGen — генератор иконки; TarGz — архив для Linux
  ui/icons/ иконка приложения (PNG 16–256), icon/app.ico — для exe
```

Иконка нарисована программно (`IconGen`): серверные блоки со светодиодами и шестерёнка администрирования. Перерисовать после правок в `IconGen.java`:

```
java -cp out/classes ru.rasconsole.tools.IconGen src/ru/rasconsole/ui/icons icon/app.ico
```
